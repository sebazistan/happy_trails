HAPPY TRAILS — site assets, version 2.1

The folder carries the version; the files inside do not. Every page and asset
has a plain name so that links never need rewriting and replacing a file is
simply replacing a file.

WHAT IS HERE
  index.html            the main map
  trails.html           the list of trails
  wishful.html          every proposed thing, sortable by cost and priority
  about.html
  contact.html
  beltline.html         the finished trail — and the worked example of what
                        a finished trail's entry in trails_data.py looks like
  <eleven more>.html    one per route on the main map, placeholder content
  trail-engine.js       how a trail page works — shared by all twelve
  happy-trails.css      every colour, size and font — shared by all fourteen
  analytics.js          counting visits — inert until one line names a
                        provider. Nothing is measured until you say so.
  CHANGELOG.txt         what changed, and why. This used to be a comment at
                        the top of beltline.html; that page is generated now,
                        so the record moved somewhere a build cannot erase.
  maps/                 the map drawings, one per trail, for editing
  media/                pictures and video, one folder per trail
  social/               the 1200x630 link previews
  icons/                EVERY drawing: the legend swatches, and the coins and
                        dials a wishful stop carries
  trail link images/    one picture per trail
  wishful link images/  one picture per proposal
  sitemap.xml           written from the page list, so it cannot go stale
  robots.txt
  favicon.*

BEFORE IT GOES LIVE
  1. media/beltline/ is EMPTY of pictures — run download.ps1 inside it once to
     fetch them from the CDN. Until then the Beltline shows placeholders.
  2. The eleven placeholder trails have drawn maps and invented text. Replace
     as each one is written — and replace them in trails_data.py, NOT in the
     .html files, which are generated and will be overwritten on the next
     build. The Beltline's entry shows the shape a written trail takes.
  3. Social previews use absolute URLs built from BASE in make_meta.py. If the
     site's address is not huzzahdesign.com/happy-trails/, change it there and
     re-run, or the link previews will come out blank. sitemap.xml is built
     from the same BASE and has the same requirement.
  4. analytics.js counts nothing until its `provider` is set. Set it to
     "plausible", "goatcounter" or "cloudflare", fill in the one setting that
     one needs, and every page starts reporting — including how far down each
     trail page people actually get, which is the number that says whether the
     scrolling format is working.
  5. TWO FOLDERS HAVE SPACES IN THEIR NAMES: "trail link images" and "wishful
     link images". Every link to them is written with %20 for the spaces,
     which is correct and which every browser and server handles. If you would
     rather not have spaces in a URL at all, renaming both to
     trail-link-images/ and wishful-link-images/ is a find-and-replace across
     make_images.py, make_wishful.py, make_pages.py and trails.html.
