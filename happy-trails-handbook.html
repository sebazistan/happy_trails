The Happy Trails Handbook

Everything you are likely to want to change, and exactly where to change it. Written for the way you work now: you edit the finished HTML files and upload them to GitHub. No build step, no tools to install — a text editor and a browser are the whole kit.

01How it is put together

Every trail page is self-contained. Open beltline.html and everything about the Beltline is in that one file: its settings, its words, its list of waypoints, and its map drawing. Nothing about the Beltline lives anywhere else. That is why editing is easy — you never have to work out which of twenty files to open.

SETTINGS

The trail's facts: how long it is, which media folder its pictures come from, which map the Download button hands over.

WORDS

The corner title, and the text on the opening and closing screens.

WAYPOINTS

One entry per stop: its title, its height, its pictures, its paragraphs. This is the block you will spend your time in.

<template id="tm-artwork">

The map itself, an SVG pasted in whole. It carries the route line and one small circle per waypoint.

Two files are shared by every page and are never edited per-trail: trail-engine.js (how a trail page behaves) and happy-trails.css (how everything looks). Change one of those and all twelve trails change together.

Where everything lives

02Uploading, and knowing it worked

Three separate delays sit between your computer and the live site, and they are why a change can seem not to have landed: the upload (your browser sending files to GitHub), the deploy (GitHub publishing them — usually under a minute, occasionally several), and your own browser's cache.

The one mistake that costs an afternoon

Drag the contents of the folder into GitHub — the loose files and the folders inside it — not the folder itself. Dragging the folder puts the whole site one level down, at /site-assets-v3.0/, where nothing links to it. There is no error message anywhere; the site simply carries on showing the previous version.

  1. Upload the files. GitHub's web uploader takes about 100 files per commit, so a full site needs three or four passes; a changed-only set is one.
  2. Wait for the deploy — the Actions tab shows it, and it is done when the dot turns green.
  3. Visit happytrailstoronto.com/version.txt. It says, in one line, which version is live. If it does not say what you just uploaded, the files did not land — go back to the note above.
  4. Then hard-refresh the page you changed: Ctrl+Shift+R on Windows, Cmd+Shift+R on a Mac.
Changed-only zips

Most changes touch two or three files. A changed-only set can be dropped straight in — GitHub replaces the files with the same names and leaves the rest alone. Only use one if version.txt currently shows the version it was built against.

03Change a waypoint's words

edit the trail's own page — e.g. beltline.html

Search the file for const WAYPOINTS. Everything below it, to the closing ];, is the list of stops. Find the one you want by its title and change the text. Each entry looks like this:

// one waypoint on the Beltline
{
  marker: "#wp-moraine",          // which circle in the drawing it sits on
  title:  "Allan Rd",
  metres: 86,                     // height above sea level, for the graph
  mapLink: "https://www.google.com/maps/@43.69,-79.46,17z",
  media:  [ { src: "06-a.jpg", caption: "The gap, fifty years on" } ],
  text:   [
    "The first paragraph.",
    "The second paragraph." ]
}

Every field is optional except title and a way of placing the stop. Leave out mapLink and the Google maps button simply does not appear. Leave out media and the card has no picture.

The fields, in full

FieldWhat it does
titlethe heading on the card, and the name in the address bar
marker"#wp-something" — the circle in this page's drawing that places the stop
alonginstead of a marker: how far along the route, 0 to 1. No drawing needed.
metresheight above sea level. Drives the elevation graph and the Elevation readout.
textone string, or a list of them — one paragraph each
mediathe pictures and video. See the next section.
mapLinka Google Maps address; adds the button at the foot of the card
kind"wishful" marks it as a proposal rather than something built
cost / priority"low", "medium" or "high" — proposals only
slugthe name in the address. Set it only to keep an old link working after a retitle.
Renaming a waypoint breaks its links

The address of a stop is made from its title: "Allan Rd" becomes beltline.html#allan-rd. Retitle it and every link pointing there — including the ones on the Wishful thinking page — lands at the top of the trail instead. To rename and keep the old links working, add the old name as a slug: slug: "allan-rd",

Links inside a paragraph

The paragraphs may contain links. The whole paragraph is wrapped in double quotes, so use single quotes inside it — double quotes would end the paragraph early and break the page.

text: [
  "A trench blasted through Midtown for the <a href='https://en.wikipedia.org/wiki/Spadina_Expressway' target='_blank' rel='noopener'>Spadina Expressway</a>, wiping out hundreds of houses." ]

A link leaving the site gets a small outward arrow after it automatically. One pointing at another page of this site does not.

04Add pictures and video

edit the trail's page and media/<trail>/

  1. Put the file in that trail's media folder — media/beltline/, media/humber/, and so on. The folder is named in that page's mediaFolder setting.
  2. Add it to the waypoint's media list. The filename alone is enough; the folder is added for you.
media: [
  { src: "05-a.jpg", caption: "Where the trail stops" },
  { src: "05-b.jpg", caption: "Where it could carry on" },
  { src: "05-c.mp4", caption: "From the air" } ],

Give a waypoint more than one and the card grows arrows and dots to step through them. The caption changes with the picture — in the small card it sits beside the title, and in the expanded card it is written across the bottom right of the photograph.

  • Any shape works. Portrait, square, 16:9 — everything is cropped to fill the card's window from the centre, never squashed. Aim for the long edge at 1600px or so; larger files only cost your readers time.
  • Video — .mp4, .webm, .ogv or .mov — plays silently and loops, and only while its own card is on screen. A spinner shows while it is still arriving.
  • A caption is optional. Without one the picture simply has no note.

A before-and-after slider

Two pictures of the same view, with a handle to wipe between them. Both are cropped identically, so shoot or crop them to line up.

{ before: "gap-now.jpg", after: "gap-bridged.jpg",
  caption: "What a bridge would do",
  beforeLabel: "Today", afterLabel: "With a bridge" }
Filenames are case-sensitive on GitHub

06-A.JPG and 06-a.jpg are two different files as far as the live site is concerned, even though your own computer treats them as the same. A picture that works locally and not online is nearly always this. Keep everything lower case.

05Add a waypoint

edit the trail's page

Copy an existing entry, paste it into the WAYPOINTS list, and change it. The order in the list does not matter — the page sorts the stops by where they fall along the route, so a new one slots itself in.

Placing it without touching Illustrator

Use along instead of marker: how far down the route the stop sits, from 0 at the start to 1 at the end. The waypoint is placed on the line, its name chip appears on the map, and the distance readout works out from there.

{
  along:  0.62,                    // 62% of the way along the route
  title:  "Yellow Creek",
  metres: 91,
  media:  [ { src: "09-a.jpg", caption: "Down into the ravine" } ],
  text:   [ "What there is to say about it." ]
},
Getting the fraction right

Read it off the trail itself. Scroll the trail page until the map is at the spot you want and look at the Complete readout in the bottom right — 62% means along: 0.62. Adjust and reload until the chip sits where you want it.

Placing it by eye, in Illustrator

The precise way, and the one the existing waypoints use. In the trail's Illustrator file, draw a small circle where the stop belongs and name it wp-yellowcreek. Export SVG (File ▸ Export ▸ Export As ▸ SVG, Styling: Presentation Attributes, Object IDs: Layer Names), then paste the whole SVG into the page between <template id="tm-artwork"> and </template>, replacing what is there. Then point the waypoint at it with marker: "#wp-yellowcreek".

The circle does not have to sit exactly on the line — the page snaps the stop to the nearest point of the route. Near enough is enough.

A marker that is not in the drawing is skipped silently

If marker names a circle the artwork does not have, that waypoint simply does not appear — no error on the page. Press F12 and look at the Console: it says waypoint marker "#wp-…" is not in the artwork — skipping "…". That message is the fastest way to catch a typo.

06Add a proposal

edit the trail's page and wishful.html

A proposal is an ordinary waypoint with three more fields. It turns purple, it hides behind the Wishful thinking switch, and its card carries a coin for what it would cost and a dial for how badly it is wanted.

{
  along:  0.31,
  title:  "Eglinton gap",
  metres: 104,
  kind:   "wishful",  cost: "medium",  priority: "high",
  media:  [ { src: "eglinton-gap.jpg", caption: "Where the path gives up" } ],
  text:   [ "What is wrong, and the specific thing that would fix it." ]
},

cost and priority are each "low", "medium" or "high". Both are required on a proposal — they are what the Wishful thinking page's sliders sort on.

The Wishful thinking page does not update itself

It is a separate page with its own list of cards, so a proposal added to a trail will not appear on it until you add it there too. Four small edits, below.

In wishful.html

  1. Make the picture. Save a 1000×560 image into wishful link images/, named after the waypoint's address — eglinton-gap.png.
  2. Copy a card — any <article class="wt-card"> block — paste it in beside the others, and change the six things marked below.
  3. Update the three counts. Search for countAll and change "Showing 1 of 12", "Showing all 12" and "Showing %s of 12" to the new total.
  4. Update the opening sentence — it begins "Twelve places where the trail network stops…"
<article class="wt-card" data-cost="medium" data-priority="high"
         data-trail="The Beltline" data-title="eglinton gap">   <!-- lower case -->
  <div class="wt-shot" style="background-image:url('wishful%20link%20images/eglinton-gap.png')"></div>
  <div class="wt-body">
    <div class="wt-on">The Beltline</div>                    <!-- which trail -->
    <h3><a class="wt-open" href="beltline.html#eglinton-gap">Eglinton gap</a></h3>
    <p>One sentence on what is missing and what would fix it.</p>
    <div class="wt-marks">
      <span class="wt-mark is-cost"><img src="icons/cost-medium.svg" alt=""
        width="48" height="48"><span><small>Cost</small><b>Medium</b></span></span>
      <span class="wt-mark is-priority"><img src="icons/priority-high.svg" alt=""
        width="48" height="48"><span><small>Priority</small><b>High</b></span></span>
    </div>
    <div class="wt-go">See it on the map <span aria-hidden="true">&rarr;</span></div>
  </div>
</article>

The data-cost and data-priority attributes are what the sliders filter on, and they must match the words shown in the two marks and the icon filenames (icons/cost-low.svg, icons/priority-high.svg, and so on). data-title is the title in lower case; it is only used for sorting.

The link on the card — beltline.html#eglinton-gap — is the whole point of the page. Following it opens that waypoint's card expanded, over the map, with the trail already standing at the right place.

07A trail's own settings

edit the trail's page, near the top

Above the waypoints sit two small blocks. SETTINGS holds the trail's facts:

const SETTINGS = {
  trailLength:    10.2,                        // km end to end. Every distance
                                              // on the page is worked out from this.
  mediaFolder:    "media/beltline/",           // where its pictures live
  mapFile:        "maps/beltline-map.svg",     // what Download hands over
  trailImage:     "trail%20link%20images/beltline.png",
};

And WORDS holds everything written on the page that is not a waypoint:

const WORDS = {
  cornerKicker:  "Type: Railpath · Length: 10.2 km",   // top left, small
  cornerTitle:   "The Beltline",                       // top left, large
  openingKicker: "Midtown Toronto",
  openingTitle:  "The Beltline",
  openingBody:   "The paragraph on the opening screen.",
  closingTitle:  "The end of the line",
  closingBody:   "The paragraph on the closing screen.",
};
Two spaces, written as %20

The folders trail link images and wishful link images have spaces in their names, and a space cannot appear in a web address — it is written %20. Copy those paths exactly as they appear; a literal space there is a broken picture.

08Replace a map

edit the trail's page and maps/

A trail's drawing is pasted into its page, between <template id="tm-artwork"> and </template>, near the bottom of the file. To replace it, export SVG from Illustrator and paste the whole thing in place of what is there.

Export with Styling: Presentation Attributes and Object IDs: Layer Names. Three names inside the drawing matter:

Name in IllustratorWhat it becomes
routethe line the page walks. Exactly one per trail map.
wp-somethinga small circle marking a waypoint, one per stop that uses a marker
link-1, link-2…a small circle where this trail meets another; the page puts a button there

Then save the same SVG into maps/ under the name in that page's mapFile setting, so the Download button hands over the new drawing rather than the old one.

09Add a whole new trail

This is the one job that touches several files. In order:

  1. Copy a trail page that is closest in shape to the new one and rename it — rouge.html. Change its SETTINGS, its WORDS, and its WAYPOINTS.
  2. Paste its drawing in (section 08) and save a copy into maps/.
  3. Make its media folder: media/rouge/, and point mediaFolder at it.
  4. Make its two pictures: trail link images/rouge.png at 1000×560, for the opening card and the trails page.
  5. Add its card to trails.html — copy one that is already there and change the name, the picture, the type and length line, and the link.
  6. Add it to the main map. In index.html, find const ROUTES and add a line. layer is the name of the group in the main map's artwork that holds this route's highlight; x and y are where its button sits, in the artwork's own coordinates.
{ label: "Rouge", layer: "rouge", x: 4200, y: 900,
  href: "rouge.html", needs: ROUTE_NEEDS },
  1. Add the route to the main map's artwork — a group named rouge holding the highlighted line, pasted into index.html's artwork the same way. A route with no group still gets a button; it just has nothing to light up when you point at it.
  2. Add it to the navigation if it should be there, and to sitemap.xml.
Do it in two sittings

Steps 1 to 5 give you a working trail page you can open and read, with its own map and pictures, reachable from the trails list. Steps 6 and 7 put it on the main map. There is no harm in the gap: a trail with no route button is simply not on the map yet.

10Colours, sizes, behaviour

edit happy-trails.css or trail-engine.js

Both files open with one long block of numbers, each with a note saying what it does and what happens if you change it. You will not need to read past those blocks. Everything in them applies to the whole site at once.

In happy-trails.css — the look

VariableWhat it sets
--accentthe red used for buttons and highlights
--route-linethe green of a built trail, on the map and the graph
--route-line-wishthe magenta of a proposed one
--card-bodythe size of the paragraph text on a card. A tenth of a millimetre here is another line of text.
--card-text-linesthe most lines a small card will show at once before paging
--card-mediathe shape of the picture window — 4/3
--card-widthhow wide the card beside the map may be
--big-media-partin the expanded card, the share of the width the picture takes. Raising it makes the picture bigger and the card taller.
--caption-sizethe picture's caption
--bar-heightthe navigation bar, which everything else measures down from

In trail-engine.js — the behaviour

SettingWhat it does
pageHeighthow much scrolling a trail takes, in screenfuls. Bigger = slower walk.
zoomWalkinghow close in the map sits while walking
videoAutoplaywhether a video starts by itself when its card arrives
cardCanGrowoffer the expand button at all
cardGrowsFromthe narrowest window that gets it — 1100px
bigOnArrivalwhich links open expanded. "wishful" is the Wishful thinking page's journey.
wishfulOnwhether proposals show before the switch is touched
cardsCanBeClosedthe × in a card's corner

A setting can also be changed for one trail only: add it to that page's own SETTINGS block, which overrides the shared default. That is how a trail could get a slower walk or a closer zoom than the rest without affecting anything else.

Counting visits

analytics.js does nothing until you set provider to "plausible", "goatcounter" or "cloudflare" and fill in the one setting it needs. No cookies, no identifiers, and it honours Do Not Track. It also records how far down each trail page people actually get — a quarter, half, three quarters, the end — which is the number that says whether the scrolling format is working.

11The five traps

Nearly every broken page comes from one of these. A trail page that goes blank or loses its waypoints has almost certainly hit the first two.

  1. A missing comma. Every waypoint in the list ends with }, — except the last, which may end with just }. Paste a new one in and it is easy to leave the comma off the one above it.
  2. A double quote inside a double-quoted line. Use single quotes inside paragraphs, or curly quotes (" ") for actual quotation marks. A straight double quote ends the text early and everything after it stops making sense.
  3. Capital letters in filenames. The live site is case-sensitive; your computer is not. Keep everything lower case and this never happens.
  4. A space in a path. Written %20. Only affects the two "link images" folders.
  5. A marker that is not in the drawing. The waypoint disappears without a word. The Console (F12) names it.
If a page goes blank

Press F12 and read the first red line in the Console. It names the file and the line number, and the mistake is nearly always on that line or the one above it. Nothing is lost: the previous version is still on GitHub under the file's History.

12Check before you upload

Everything works from your own computer — no server needed. Double-click the page you edited and it opens in your browser exactly as it will online, with one exception: video and some pictures may not load from a local file, which is not a fault.

  1. Open the trail page and scroll it from top to bottom. Every waypoint you expect should appear, in order, with its picture.
  2. Press F12 and look at the Console. Silence is the pass mark. A yellow warning about a marker means a waypoint is being skipped.
  3. Click a waypoint's expand button and check the picture and the words in the big view.
  4. If you added a proposal, open wishful.html, check the count is right, move the sliders, and follow your new card's link — it should open that waypoint expanded, over the map.
  5. Narrow the window to about the width of a phone. The card should go full width and the expand button should disappear.

Then upload, wait for the green dot, check version.txt, and hard-refresh.

The short version

Words, pictures and waypoints all live in one place: the WAYPOINTS block inside that trail's own HTML file. Pictures go in media/<trail>/. A proposal needs the same entry plus kind, cost and priority — and a matching card on wishful.html, which is the only thing on the site that does not update itself.

Everything else — colours, sizes, how far you scroll, how the cards behave — is a numbered setting at the top of happy-trails.css or trail-engine.js, and changes the whole site at once.
